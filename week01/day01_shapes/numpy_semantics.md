## 0. 先建立正确的心智模型

一个 `ndarray` 是三个东西：

```
ndarray = 一块连续内存  +  一个 shape（怎么解读这块内存）  +  一个 dtype
```

**关键领悟：`shape` 是「解读方式」，不是数据本身。**

所以 `reshape` / `transpose` / 切片 都是在**换一种解读方式**，有时根本不复制内存（叫"视图"）。

### 数学矩阵 vs NumPy 数组的区别

| | 数学 | NumPy |
|---|---|---|
| 维度 | 矩阵是 2-D 对象，向量是特殊的矩阵 | **n 维都行**，1-D 数组有自己独立的行为 |
| 类型 | 只有矩阵 | 标量/1-D/2-D/3-D… 行为各不相同 |
| 乘法 | 只有一种矩阵乘法 | `A @ B`（矩阵乘）和 `A * B`（逐元素乘）是**两个东西** |

**最后一行是最大的坑**：数学里你不区分，NumPy 里必须区分。

```python
A * B    # 逐元素相乘（Hadamard 积），要求 shape 能广播
A @ B    # 矩阵乘法，要求内维相消
```

## 1. `axis=k` 的语义

### 先澄清一个常见混淆：`axis` 是参数，不是函数

| | 回答什么问题 | 类别 |
|---|---|---|
| **`sum` / `mean` / `norm`** | **做什么运算** | 函数（动作） |
| **`axis`** | **在哪个方向上做** | 参数（方向） |

它们不是二选一的关系——`axis` 是**传给**这些函数的参数。不能问"`axis` 和 `mean` 有什么区别"，就像不能问"走路和往北有什么区别"。

**而且 `axis` 不是 `mean` 专属的**，它是 NumPy 所有归约函数的通用参数。学会一次，处处能用：

```python
x.sum(axis=0)                 # 求和
x.mean(axis=0)                # 平均
x.max(axis=0)                 # 最大值
x.std(axis=0)                 # 标准差
x.argmax(axis=0)              # 最大值的位置
np.linalg.norm(x, axis=0)     # 范数
img.mean(axis=(2, 3))         # 一次压两维
```

—— **全部遵守同一条规则。**

### 在归约函数里：`axis=k` = "第 k 维要消失"

```
x.shape = (4, 3)
            ↑  ↑
         axis=0  axis=1

x.sum(axis=0)  →  沿着 axis=0 方向压扁  →  (3,)    ← 第 0 维没了
x.sum(axis=1)  →  沿着 axis=1 方向压扁  →  (4,)    ← 第 1 维没了
x.sum()        →  全部压扁             →  ()      ← 标量
```

**视觉示意**（`x.shape = (2, 3)`）：

```
       列0  列1  列2
行0  [   1    2    3  ]
行1  [   4    5    6  ]
         ↑    ↑    ↑
         axis=0 是"行号变化"的方向（竖着）

axis=0 压 → 每列塌成一个数 → (3,)  [2.5, 3.5, 4.5]
axis=1 压 → 每行塌成一个数 → (2,)  [2.0, 5.0]
```

### ⚠️ 关键陷阱：指定的是"要压掉的"，不是"要保留的"

很多人会想"我要保留第 1 维，所以写 `axis=1`"—— **正好反了**。

> **`axis=k` 指定的是「要被压掉的那一维」。**

### 放到深度学习的语义里

`x` 是 `(B, D)` = `(batch, feature)`：

| 写法 | 含义 | 结果 |
|---|---|---|
| `x.sum(axis=0)` | **跨样本**相加 | `(D,)` |
| `x.sum(axis=1)` | 每个样本**内部跨特征**相加 | `(B,)` |

新手最容易混的就是这个。**永远先问自己："我要在哪个方向上归约？"**

### axis 可以传元组

```python
img.shape = (4, 2, 32, 32)          # (B, C, H, W)
img.mean(axis=(2, 3)).shape         # 一次压掉两维 → (4, 2)
```

### ⚠️ 但 `axis` 不是只有"消失"这一种含义

`axis` 的**通用含义**是"**第 k 个下标在变化的方向**"（= 指定位置）。
至于那一维最后**消失 / 变大 / 挪位置**，**取决于函数**：

| 函数类型 | 例子 | `axis=k` 的含义 | 那一维的结果 |
|---|---|---|---|
| **归约** | `sum` / `mean` / `max` / `norm` | 沿这个方向**收成一个数** | **消失** |
| **拼接** | `np.concatenate` | 沿这个方向**把数组接起来** | **变大** |
| **插维** | `np.expand_dims` | 在这个**位置插入**新维 | **多一个 1** |

```python
a = np.ones((2, 3)); b = np.ones((2, 3))

np.concatenate([a, b], axis=0).shape    # (4, 3)   ← 第0维 2 变 4（变大，没消失）
np.concatenate([a, b], axis=1).shape    # (2, 6)   ← 第1维 3 变 6

np.expand_dims(x, axis=0).shape         # (1, 4, 3)  ← 在第0位插一个 1
np.expand_dims(x, axis=-1).shape        # (4, 3, 1)  ← -1 = 最后一位
```

**同样写 `axis=0`，三种函数干三件完全不同的事。** 所以别死记"axis 就是压掉"，要记"**axis 指定位置，行为看函数**"。

### 解题口诀：反着推

问题永远是"**剩哪一维**"，所以从结果反推：

```
要保留 feature (3,)，压掉 batch    ->  axis=0
要保留 batch  (4,)，压掉 feature  ->  axis=1
两个都不要                         ->  不给 axis
两个都要保留（为了广播）           ->  keepdims=True
```

**"我要剩什么" → 反推 "我要压什么"** —— 比正着想不容易错。

### 对照：PyTorch 怎么叫

```python
x.mean(axis=0)                 # NumPy
torch.mean(x, dim=0)           # PyTorch —— 叫 dim
np.concatenate([a,b], axis=0)  # NumPy
torch.cat([a,b], dim=0)        # PyTorch —— dim + 函数名也变了
np.expand_dims(x, axis=0)      # NumPy
x.unsqueeze(0)                 # PyTorch —— 连 axis 参数都没有了
```

## 2. Broadcasting（广播）

### ⚠️ 这**不是数学概念**，是 NumPy 的工程发明

数学里没有"广播"。它的目的是：**让不同 shape 的数组能做逐元素运算，而且不真的复制数据**（省内存、省时间）。

所以你不能从线代推出它——只能记住规则。

### 三条规则

```
从最右边开始对齐，逐维比较：

  ① 相等          → 通过
  ② 其中一个是 1   → 拉伸到另一个的长度
  ③ 都不等且都不是 1 → 报错 ValueError
```

缺的维度**当作 1** 处理。

### 判定流程（照着走）

**例 1：能广播**

```
A.shape = (4, 3)
B.shape = (3,)

第①步 从最右对齐：
        A:  4   3
        B:      3

第②步 逐维比较（从右往左）：
        最右维:  3 vs 3   → 相等 ✓
        第 0 维: 4 vs 缺失 → 缺失当作 1，拉伸成 4 ✓

结果: (4, 3)
```

**例 2：报错**

```
A.shape = (4, 3)
B.shape = (4,)

对齐：
        A:  4   3
        B:      4

最右维:  3 vs 4  →  不等，且都不是 1  →  ❌ ValueError
```

### 为什么这是 DL 里最常踩的坑

看例 2：`(4,)` 在你的**语义**里像是 batch 维，但 NumPy 从**右边**对齐，把它当成了最后一维。

> **语义和机制不一致** —— 这就是 `keepdims` 存在的全部理由（见 §5）。

### 手算模板

以后遇到广播，在纸上这样写：

```
   A:  _  4  3
   B:  _  _  3
      ─────────
       ✓  ✓        →  (4, 3)
```

## 3. 1-D 数组在 `@` 里的提升规则 ★

数学上你知道矩阵乘法 `(m,k) @ (k,n) → (m,n)`。但 NumPy 允许 1-D 参与运算，规则是：

| 1-D 在 | 被当成 | 结果 |
|---|---|---|
| **右边** | 列向量 `(k, 1)` | 算完**去掉后面**那个 1 |
| **左边** | 行向量 `(1, k)` | 算完**去掉前面**那个 1 |

### ⚠️ 注意这是不对称的

设 `b.shape = (5,)`，`W.shape = (3, 5)`，于是 `W.T.shape = (5, 3)`：

```
b @ W.T   →  b 在左，当行向量 (1,5)
             (1,5) @ (5,3) → (1,3) → 去掉前导 1 → (3,)   ✓

W.T @ b   →  b 在右，当列向量 (5,1)
             (5,3) @ (5,1) → 内维 3 vs 5 → ❌ 报错
```

**同样一个 b，站左边能跑，站右边就炸。** 你没法从数学判断 NumPy 会怎么处理——只能记规则。

### 工程结论

> **深度学习的代码里永远显式写 `(B, D)`，不要依赖 1-D 自动推断。**

因为读代码的人（包括三个月后的你）根本看不出哪里会炸。

## 4. `.T` / `reshape` / `transpose`

### `.T` —— 分情况，别乱用

| 维度 | 行为 |
|---|---|
| 2-D | 正常转置 ✓ |
| **1-D** | **什么都不做**！`(3,).T` 还是 `(3,)` ❌ |
| n-D（≥3） | 反转**所有**轴 → 通常不是你想要的 ❌ |

3-D 以上请用 `transpose(轴序)` 明确指定。

### `reshape` vs `transpose` —— 这是最容易写错的地方

```python
x = np.arange(6).reshape(2, 3)
# x = [[0, 1, 2],
#      [3, 4, 5]]
```

**`x.reshape(3, 2)`** —— 按内存顺序重新切分：

```
内存里的顺序:  0 1 2 3 4 5

切成 (3,2):   [[0, 1],
               [2, 3],
               [4, 5]]
```

**`x.T`** —— 真的转置：

```
[[0, 3],
 [1, 4],
 [2, 5]]
```

**结果完全不同！** `reshape` 只是换了个"切法"，`transpose` 才是换轴。

### 3-D 时更明显

```python
seq.shape = (4, 6, 3)        # (B, T, D)

seq.reshape(6, 4, 3)         # shape 对了，但数据是乱揉的
seq.transpose(1, 0, 2)       # shape 一样，数据才是真的换了轴
```

两者 shape 都是 `(6,4,3)`，但**内容完全不同**。这是 Attention 里最容易埋 bug 的地方。

### 判断口诀

> **换维度顺序 → `transpose`**
> **合并 / 拆开维度 → `reshape`**

### 补充：视图 vs 拷贝

两者都尽量返回**视图**（不复制内存）。但 `transpose` 之后内存不连续，此时再 `reshape` 可能触发一次真实拷贝。平时不用管，但看到 `.copy()` 或性能问题时要知道这个背景。

## 5. `keepdims` —— 为什么必须有它

### 问题

`sum / mean / max / norm(..., axis=k)` 默认把第 k 维**删掉**。

```
x.shape = (4, 3)

m = x.mean(axis=1)          # (4,)   ← 第 1 维被删了
x - m                       # ❌ (4,3) - (4,) → 从右对齐 3 vs 4 → 报错
```

### 解法

```python
m = x.mean(axis=1, keepdims=True)    # (4, 1)  ← 第 1 维变成 1，而不是消失
x - m                                # ✓ (4,3) - (4,1) → 广播成 (4,3)
```

### 为什么这样就好了

回到 §2 的广播规则：

- `(4,)` 被从右对齐 → 当成最后一维是 4 → 和 `x` 的 3 冲突 ❌
- `(4,1)` 最后一维是 **1** → 可以拉伸成 3 → 通过 ✓

> **`1` 可以被广播，消失的维度不能。**

### 口诀

> **归约之后还要参与运算 → 加 `keepdims=True`**

典型场景：归一化（减均值 / 除标准差）、LayerNorm、BatchNorm、梯度裁剪。

## 6. `np.linalg.norm` 的 axis

L2 范数 = √(各元素平方和)，也就是"长度"。

```python
x.shape = (4, 3)

np.linalg.norm(x)                       # 不给 axis → 整个数组拉平求 → 标量 ()
np.linalg.norm(x, axis=1)               # 沿第 1 维求 → 每行一个长度 → (4,)
np.linalg.norm(x, axis=1, keepdims=True)# (4, 1)
```

规则和 §1 一致：**给了 axis，那一维就消失**。所以想要广播就得配 `keepdims=True`：

```python
x / np.linalg.norm(x, axis=1, keepdims=True)   # ✓ 每行 L2 归一化 → (4,3)
x / np.linalg.norm(x, axis=1)                  # ❌ (4,3)/(4,) → 报错
```

就是 §5 那个坑，换个函数再来一次。

## 7. 速查表：数学 → NumPy

| 数学 | NumPy | ⚠️ 注意 |
|---|---|---|
| 矩阵 (m,n) | `np.zeros((m,n))` | |
| 转置 Aᵀ | `A.T` | **1-D 无效** |
| 矩阵乘法 AB | `A @ B` | 内维相消 |
| **逐元素乘** | `A * B` | **不是矩阵乘法！** |
| 点积 a·b | `a @ b` | 1-D 时返回标量 |
| 求和 Σ | `.sum(axis=k)` | 该轴消失 |
| 范数 ‖x‖ | `np.linalg.norm(x, axis=k)` | 该轴消失 |

**最容易出事的两行：**

1. `*` 和 `@` 是两回事（数学里不区分，NumPy 里区分）
2. `.T` 对 1-D 无效

### 8.6 三类高频陷阱（按出错率排序）

**① `(n,)` 对齐到最后一维，不是第 0 维** ★ 最坑

```
x      (4, 3)
norm   (4,)      ← 这个 4 是"最后一维是 4"，不是"batch 是 4"

从右对齐:  x: 4  3
         norm:    4      ← 落在这一列
                  ✗      ← 3 vs 4
```

> 你的**语义**里 `(4,)` 是 batch；NumPy 的**机制**是从右对齐。
> 想让 n 落在 batch 上，只能用 `(n,1)` —— 也就是 `keepdims=True`。

**② 广播永远不减少维数**

| | 维数 |
|---|---|
| **归约**（`sum` / `mean` / `norm`） | ✅ **会消失** |
| **广播**（`+` `-` `*` `/`） | ❌ **只会变多不会变少** |

看到 `+ - * /`，输出维数 = 参与运算的数组里**维数最多的那个**。

**③ 1-D 在 `@` 里的方向**

```
在哪边，就补在哪边：
  左 -> 补前面 (1,k) -> 去掉前导 1
  右 -> 补后面 (k,1) -> 去掉尾部 1
```

> **工程结论：DL 代码里永远显式写 `(B,D)`，永远不用 1-D。**
